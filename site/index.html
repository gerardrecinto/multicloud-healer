Restart the stuck pod. Not on the first bad check.

A Kubernetes controller that acts only after consecutive failed health checks. It restarts stuck pods, and cordons and drains unhealthy nodes through the Eviction API, on both EKS and GKE.

Mark something unhealthy, then run check cycles. The controller acts only after the threshold of consecutive failures.

Node remediation is exercised here against a fake API, matching the repo's own tests. The README is explicit that this project was demonstrated on a local kind cluster, not on production EKS or GKE.

How it works

Acting on one bad health check causes more outages than it fixes. So it counts.

1

Check, then count

Each cycle checks every pod and node. A tracker counts consecutive failures per object and fires once, the moment the count reaches the threshold.

2

Pick the smallest fix

A stuck pod is deleted so its controller recreates it. An unhealthy node is cordoned, then drained through the Eviction API, which respects PodDisruptionBudgets.

3

Know when to stop

DaemonSet and mirror pods are skipped, as in kubectl drain. A cap on repeat remediations stops it from restarting the same pod forever.

One adapter for EKS and GKE

The two clouds label the same things differently. The adapter reads whichever labels are present, so the rest of the controller sees one shape. Nodes in the demo above carry real label names from both.

Run it on a cluster

Python 3.12 or later. Start with --dry-run.

pip install -r requirements.txt
python -m multicloud_healer.controller \
  --namespace default \
  --label-selector app=flaky \
  --failure-threshold 3 \
  --dry-run
# local walkthrough on kind
bash demo/run_demo.sh

See the README for the node flags and the Kubernetes manifests in k8s/.

What this does not do
  • It is a proof of concept. It has not been run against production EKS or GKE.
  • Restarting a pod does not fix a bad image or config. The repeat cap exists for that.
  • This page uses Kubernetes client 31 because the pinned 36 needs a newer pydantic than the browser runtime ships. The logic under test is the same.
